# V2 完整重构标准

本文件替代“继续按旧服务拆文件”的实现方向。现有 `portal/` 拆分保留为实验和回归依据，不是目标架构。真实灰度入口继续运行，稳定版不因此更新。

## 先定义职责，再写实现

目标仍是一个模块化应用，不引入微服务、消息总线或通用工作流框架。保留现有技术栈；成熟的 GPUQ、容器、文件传输实现可作为底层适配器复用。

| 边界 | 职责 | 不允许承担的职责 |
| --- | --- | --- |
| `contracts/` | 网页／CLI 共用的请求、响应、错误码和事件定义 | 数据库、权限决策、页面状态 |
| `client/` | 共用 SDK：登录、调用、回执、进度、原编号恢复 | 第二份调度、授权或存储业务规则 |
| `api/` | HTTP、身份解析、参数解析、调用用例、响应映射 | 选卡、复制数据、直接操作业务表 |
| `application/` | 提交任务、读取数据、上传、取消等独立用例；事务和副作用顺序 | HTTP/Cookie、SSH、具体 SQL、UI 文案 |
| `domain/` | 任务、租约、项目、数据来源、状态转换和调度决策 | 网络、磁盘、计时器、启动服务 |
| `infrastructure/` | 数据库仓储、GPUQ、节点执行、文件读取和传输适配器 | 私自决定业务规则或改变任务归属 |
| `bootstrap/` | 显式组装依赖、启动和关闭后台服务 | 在运行时给服务对象动态塞方法 |
| 网页／CLI 外壳 | 展示、命令解析、文件选择及终端交互 | 绕开 SDK 再实现接口或恢复逻辑 |

依赖只能向内：`api → application → domain`。适配器实现用例声明的接口，由 `bootstrap` 注入；领域和用例不反向导入具体适配器。客户端只依赖共享契约与 SDK。

不提前创建一堆空目录或空接口。每个新模块必须随一个真实用例落地，并能解释其输入、输出、所有权和依赖。

## 明确状态和副作用的所有者

- 账号与授权由身份模块管理，任务状态由任务模块管理，GPU 预留／租约由唯一调度权威管理；客户端不推导另一份权威状态。
- 调度决策接收明确快照并输出计划，不直接启动进程。执行适配器执行计划，不自行抢卡或改优先级。
- 数据读取、入库发布、缓存准备、传输是不同用例。读取已有目录不能隐式复制或因缓存空间不足而拒绝；固定版本和缓存保留各自语义。
- 超时表示观察或操作结果未确认，不自动把任务改为失败、不换编号重提。将观察状态与任务执行状态分开定义。
- 写入请求的身份、幂等编号、事务提交点、外部副作用与恢复查询必须在用例中明确；不能散落在 UI、API 和执行器的不同分支里。

## 代码规则

1. 禁止把整个 `PortalService`、全局 `context/services` 容器或可变全局对象传给业务类。只注入该用例实际需要的命名依赖，例如 `jobRepository`、`scheduler`、`nodeExecutor`。
2. 不继承演示服务实现生产业务，不使用 `installX(service)` 动态扩展业务对象。演示环境使用同一用例和替代适配器。
3. 外部数据在边界解析一次，内部传明确的对象。权限、租约、完整性和跨异步边界的必要复查保留在负责它的模块，不到处重复检查同一字段。
4. 禁止在业务深处猜旧版本、补默认权限、用报错字符串控制流程或吞掉异常换条路径重试。确需兼容时使用单独、有版本和退役条件的适配器。
5. 函数名称必须反映副作用；准备、释放缓存不能藏在名为 `read` 的新接口里。类用于管理明确的状态／依赖，纯规则用普通函数。
6. 不为减少行数牺牲可读性，也不为“分层”增加无意义转发。一个职责一个实现，新增抽象必须有实际调用链和测试支撑。

## 开工顺序与完成条件

1. 先建立功能清单、统一 API 契约、领域对象／状态转换和持久化所有权；现有能力逐项标记保留、替换或经确认退役。没有用户确认不删功能。
2. 选“读取已有数据”做第一条完整链路：网页／CLI → SDK → API → 用例 → 数据访问适配器，同时覆盖原目录、仓库版本、缓存三种来源。
3. 再实现任务提交／查询／取消、调度／抢占、项目／容器、上传／恢复等完整链路。新测试针对业务契约，不绑定旧文件名和私有方法。
4. 每条链路需证明两种客户端业务结果一致，并覆盖正常、失败、并发、权限变化和断连恢复。旧回归失败必须分类，不全当作 bug，也不全当作废弃测试。
5. 真实灰度共用权威任务和资源状态。新后端接入前必须明确单写者通路；不能因为灰度入口已上线，就宣称新后端正在服务。
6. 全部保留能力验收、数据兼容和回退演练通过后才替换默认实现；不得将影子数据库覆盖生产或中断既有训练。切换影响提前说明。

当前状态：标准已确定，尚未宣称统一契约、完整新内核或业务迁移已完成。旧实现被冻结为参考，后续新实现按上述边界进入独立源码树。
