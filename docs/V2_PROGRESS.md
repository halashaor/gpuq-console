## 检查点 1：读取契约与用例

Git 回退点：`1444051`。

- 新实现位于 `src/`，不导入旧 `PortalService`、演示服务或 `installX`。
- `/api/v2/data/read-location` 明确区分 `directory`、`warehouse`、`cache`，不接受宿主路径或调用者自报用户身份。
- `ResolveDataRead` 只依赖 `access.requireRead` 和 `sources.inspect`，没有复制、准备、容量检查或调度依赖。
- 解析得到的是读取位置观察，不是已挂载证明、训练准入或数据租约。
- 五项契约／用例测试通过：三种来源、无隐式回退、无复制依赖、拒绝时零 I/O、异步期间撤销权限和私有字段不外泄。

## 检查点 2：真实目录、HTTP 与共用 SDK

Git 回退点：`759f51c`。

- `LocalSourceReader` 只通过注入的目录查询接口取得路径，再用只读文件描述符检查目录；目录缺失、尚未就绪和不可读分别返回，不改走其他来源。
- 同一个 `DataClient` 和 `JsonHttpTransport` 已在真实 Chromium 和 Node 运行，Cookie／令牌调用同一个 HTTP 接口；认证和来源权限仍是显式端口，未接生产身份库。
- 16 项 V2 测试通过，另有真实浏览器对照通过。覆盖 100 个并发读者共用原 inode、源文件不变、缓存缺失不阻断原目录／仓库、拒绝时零目录查询、来源回包不匹配、报文上限及错误不泄露宿主路径。
- 首轮真实浏览器发现 `fetch` 被当作对象方法调用造成非法接收者；已改为独立函数调用，重新验证通过。
- 新链路不导入旧服务，未替换生产或现役灰度的状态所有者；没有提交 GPU 任务。

## 检查点 3：共用客户端会话生命周期

- `ClientSession` 独占凭据快照和请求生命周期；HTTP 层不保存第二份凭据。身份改变时关闭旧请求上下文，新调用只使用新凭据。
- 返回 HTTP 响应后、解析正文后都确认会话仍有效；即使传输实现忽略取消信号，也不交付旧账号的迟到结果或错误。
- 单个请求取消和退出登录上下文是不同动作；取消查询不会注销会话，也不会重放调用。
- 20 项 V2 测试通过，真实浏览器验证同一 SDK 的 Cookie／令牌调用、关闭后零请求、重新打开及源文件不变。
- 这不是完整登录系统：服务器会话签发／撤销、令牌持久化和真实授权适配器仍待实现；未改变生产登录或现役灰度。
