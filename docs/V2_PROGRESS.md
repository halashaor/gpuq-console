# V2 进度与回退点

完整目标仍是统一契约、SDK、用例、领域和适配器的重建及真实灰度验收，不以某一条链路通过作为整体完成。

## 保留能力清单

| 范围 | 需覆盖的能力 | 当前 V2 状态 |
| --- | --- | --- |
| 身份 | 登录持久化、角色、机器／数据权限、账号管理 | 待实现；现役身份仍为权威 |
| 任务 | 提交、排队、指定／任意选卡、多机候选、共享、优先级、抢占、保存恢复、合法弹性卡数 | 待实现 |
| 项目 | 代码／镜像版本、个人容器、终端重连、发布、手动同步和 Git 来源 | 待实现 |
| 数据读取 | 共享原目录、仓库固定版本、缓存版本，读写解耦 | 契约与独立用例已实现，适配器／API／SDK 待接 |
| 数据操作 | 上传和下载、原编号续传、校验、缓存准备、归档／清理／删除与恢复保护 | 待实现 |
| 观测协作 | 任务名和提交者、进度、日志、完成反馈、通知、留言及清理规则 | 待实现 |
| 客户端 | 网页和 CLI 共用 SDK／业务接口；平台相关 I/O 为客户端适配器 | 待实现 |
| 灰度切换 | 真实用户显式加入、单状态写入者、旧任务兼容、回退 | 现役入口已存在；新内核尚未接管 |

历史上已经停用的接口保持明确的兼容拒绝，不根据旧测试擅自恢复中转或权限入口；若需改变现役能力，单独确认。

## 检查点 1：读取契约与用例

- 新实现位于 `src/`，不导入旧 `PortalService`、演示服务或 `installX`。
- `/api/v2/data/read-location` 明确区分 `directory`、`warehouse`、`cache`，不接受宿主路径或调用者自报用户身份。
- `ResolveDataRead` 只依赖 `access.requireRead` 和 `sources.inspect`，没有复制、准备、容量检查或调度依赖。
- 解析得到的是读取位置观察，不是已挂载证明、训练准入或数据租约。
- 五项契约／用例测试通过：三种来源、无隐式回退、无复制依赖、拒绝时零 I/O、异步期间撤销权限和私有字段不外泄。

下一检查点：真实文件系统适配器、统一 HTTP API 和共用 SDK；两种客户端使用相同输入输出和错误契约。生产与现役灰度执行链暂不改动。
